# AGENTS.md

## Project purpose

This is a voice-avatar application generated by `create-spatius-app`. It has
three runtime boundaries:

- `web/`: React and Spatius AvatarKit in the browser.
- `worker/`: the same-origin Cloudflare Worker API.
- `agent/`: a Python LiveKit Agents worker deployed to LiveKit Cloud.

Vite and the Cloudflare plugin deploy `web/` assets and `worker/` API routes as
one Cloudflare Worker. The Python agent remains independently deployable.

## Commands

- Configure local credentials with a human/PTY present:
  `npx create-spatius-app setup . --interactive`
- Install JavaScript dependencies: `__SPATIUS_JAVASCRIPT_INSTALL_COMMAND__`
- Install Python dependencies: `__SPATIUS_PYTHON_INSTALL_SUMMARY__`
- Start frontend, Worker, and Python agent together: `__SPATIUS_DEV_COMMAND__`
- Start only frontend and Worker: `__SPATIUS_WEB_DEV_COMMAND__`
- Run frontend/Worker checks: `__SPATIUS_CHECK_COMMAND__`
- Run Python checks: `__SPATIUS_AGENT_CHECK_COMMAND__`
- Regenerate Cloudflare types: `__SPATIUS_CF_TYPEGEN_COMMAND__`
- Deploy frontend and Worker: `__SPATIUS_DEPLOY_COMMAND__`
- Run the agent locally: `__SPATIUS_AGENT_DEV_COMMAND__`
- Deploy the agent: run `lk agent deploy` from `agent/`

## Runtime contract

`POST /api/session` is the only browser bootstrap endpoint. It returns a
short-lived LiveKit participant token, LiveKit server URL, unique room name,
and public Spatius rendering configuration. It embeds an explicit dispatch for
`spatius-agent` with session-specific JSON metadata. The versioned contract is
defined in `contracts/agent-dispatch-metadata.schema.json`; its first consumer
is `agent/src/dispatch_metadata.py`.

Keep the agent name synchronized between `wrangler.jsonc`, `.dev.vars`, and the
`@server.rtc_session` decorator in `agent/src/agent.py`.

## Secrets

- Credential setup is local-only. It does not upload Cloudflare Worker secrets,
  configure LiveKit Cloud agent secrets, or deploy either runtime.
- Ordinary agent, CI, JSON, dry-run, and `--yes` creation must not trigger
  authentication. A coding agent may launch the guided flow only with a PTY and
  explicit `--setup --interactive`, or rerun
  `npx create-spatius-app setup . --interactive` after creation.
- Users can pass `--no-setup` during generation, or manually copy
  `.dev.vars.example` and `agent/.env.example` to the ignored local files.
- Browser code must never receive `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`, or
  `SPATIUS_API_KEY`.
- `.dev.vars` and `agent/.env.local` are ignored and must not be committed.
- Public Spatius app/avatar IDs may be returned by the session endpoint.
- Keep the avatar ID in Worker/business-layer configuration and pass it to the
  agent through dispatch metadata; do not make it an agent deployment variable.
- Keep `CARTESIA_VOICE_ID` in Worker configuration too, passed as `voice.id`
  in dispatch metadata. Setup offers Jacqueline (feminine) and Blake (masculine).
  Missing voice metadata defaults to Jacqueline for older projects. Keep
  Sonic 3.6, expressive mode, and Krisp BVC enabled in the Python agent.
- Do not add `SPATIUS_REGION`; current Spatius clients resolve the region
  automatically.
- Do not log tokens, API keys, secrets, or complete credential-bearing request
  payloads.

## Working rules

- Preserve the three runtime boundaries unless the task explicitly changes the
  architecture.
- Keep frontend and Worker integration compatible with one Cloudflare Worker
  deployment.
- Keep the Python worker independently deployable to LiveKit Cloud.
- Use Web Platform APIs in the Worker when practical and keep request-scoped
  state out of module globals.
- Use `crypto.randomUUID()` for anonymous LiveKit room and participant IDs.
- Keep microphone activation behind an explicit user action.
- Use one host-owned LiveKit room with `singlePeerConnection: false`; attach
  Spatius before connecting. LiveKit owns the microphone and audio renderer.
- Dispose the AvatarPlayer, AvatarView, room, and local tracks when a session
  ends or its initialization is cancelled. Do not duplicate audio rendering.
- Use `useSessionMessages` for the single, always-visible transcript. Keep Python
  transcription synchronization enabled, including interruption truncation.
- The dev launcher uses compatible `lk agent dev` when installed, otherwise
  the selected Python environment. Startup must not authenticate or install
  provider CLIs, and credentials must stay out of command arguments.
- Treat `worker/session.ts` response fields as a frontend/backend contract.
- Treat the dispatch metadata schema as a Worker/agent contract. Add fields
  compatibly within a version and increment `version` for breaking changes.
- Add tests when changing token grants, dispatch behavior, routing, or error
  responses.
- Run `__SPATIUS_CHECK_COMMAND__` and `__SPATIUS_AGENT_CHECK_COMMAND__` before
  considering a change complete.

## Current product scope

The supported stack is intentionally fixed to React, Cloudflare Workers,
LiveKit Agents, LiveKit Inference, and Spatius. Future template variants may
support other voice-agent providers. Avoid introducing a premature generic
abstraction, but keep provider-specific code localized to make that evolution
possible.

- Keep optional `SPATIUS_AVATAR_BACKGROUND_URL` in Worker configuration only; never put API secrets in browser code. Background images must use HTTPS and must not block session startup.
